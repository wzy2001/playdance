## 已完成

- [x] **修复里程碑 6 崩溃：进入播放器点播放即闪退（NPE）**。
  - 现象：模拟器上打开播放页点击播放，应用崩溃退出。
  - 根因（logcat crash 堆栈确认）：`java.lang.NullPointerException: Attempt to get length of null array` 于 `syncDubbing()` 首行 `dubItemStartsMs.isEmpty()`。`viewModelScope` 用 `Dispatchers.Main.immediate`，init 块里 launch 的 200ms ticker 协程在**构造函数尚未执行完**时就跑了第一轮（首个 `delay` 之前会先调 `syncDubbing()`），而 `dubItemStartsMs` 等配音字段声明在 init 块**之后**，此刻初始化器还没执行 → 字段为 null。
  - 修复：把配音时间轴字段（`latestChunks` / `dubItemStartsMs` / `dubTimelineDurationMs` / `lastDubCorrectionRealtime`）的声明移到 init 块**之前**，并加注释说明该顺序约束。构建通过。
  - 经验：Kotlin 属性初始化按声明顺序执行；init 中用 `Main.immediate` 启动的协程若在首个挂起点前访问成员，被访问成员必须声明在 init 之前（基本类型默认 0 不炸，引用类型为 null 会炸）。
- [x] **排查「播放无声（原声/配音都没有）」**：logcat 显示模拟器音频 HAL 持续报 `android.hardware.audio@7.1-impl.ranchu pcm_writei failed: I/O error`（每次 PCM 写都失败），而 STREAM_MUSIC 音量 10/15、未静音——是**模拟器音频输出整体失效**（已知模拟器问题，录音/宿主机音频变动后可能触发），非应用 bug。处置：冷启动模拟器（Device Manager → Cold Boot Now）。用户冷启动后原声恢复。
- [x] **修复「只有原声、没有配音」——配音轨构建竞态**：
  - 取证：拉库确认 chunk 数据完好（videoId=1，块 [0,104334)，recordedMs=18605，音频文件在），配音 Player 无报错 → 是配音轨**根本没建**。
  - 根因：init 里「加载视频行（取 durationMs）」与「observeChunks 收集」两个协程无顺序保证。若 chunk 先到而 durationMs 仍为 0，`rebuildDubbingSources()` 直接返回；随后 STATE_READY 的时长校正只在 `player.duration != uiState.durationMs` 时才重建——而 MP4 的 DB 时长（MediaMetadataRetriever）与 ExoPlayer 时长都取自 mvhd、**恰好相等**（本例均 104334），于是永远不再重建，配音整段丢失。
  - 修复：STATE_READY 改为与**配音轨自身构建时长** `dubTimelineDurationMs` 比较（不等即重建），与 UI 时长解耦；空 chunk 分支也记录构建时长避免反复空重建。另给配音 Player 加 `onPlayerError` 日志监听 + 重建成功打 `Log.d`（tag `PlayerViewModel`），后续验收出问题可直接看 logcat。构建通过。
